## 会话异常证据链与电脑端优化

已核对 `acceptance/live/lease-failure-app-log-current-date.txt`：屏保于 01:36:15.133 显示、01:42:54.441 关闭，相隔 399.308 秒。`lease-failure-summary.json` 记录同一 App 进程/PID 和 `app_instance`，旧 request 的 challenge 与过期后当前 challenge 不同，助手退出码为 1，未触发验证流程的强停标记。没有证据把此次变化归因于 App 进程重启。

结合手机端的 8 秒单调时钟租约逻辑，已确认的状态链为：至少 8 秒未接受有效心跳 → `heartbeat_timeout` 使会话过期并更换 challenge → 旧心跳随后被拒为 `stale_challenge`。后者是过期后的拒绝结果，不足以单独解释最早的心跳间隙。旧工具没有记录首故障前最后一次成功心跳及逐条 ADB 时序，因此不能归责某一条 ADB 命令、FUSE 或手机轮询。

旧电脑循环每轮在完整往返之外再等待 2 秒、且约需 15 次 ADB 往返，这是已确认的效率缺陷。当前电脑工具改用固定 monotonic 节拍，以受限 stdin 原子发送邮箱请求，并输出每轮调度延迟、耗时、距上次确认时间和 ADB 分段耗时；仍保留 `-d` 与显式目标交叉校验、8 秒手机租约及失效后不自动重开。优化仅涉及电脑端，无需重装 APK；Android 冻结源码仍为 `68111e9dc4ec`。61 项工具测试和独立审查已完成，同一 APK 上的后续 329.062 秒稳定会话复测通过；此结果不用于推定所有断连、异常退出或同步故障均已验收。
