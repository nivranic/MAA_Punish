主文件为 [Phantom_Pain_Cage.jsonc](../../resource/base/pipeline/Phantom_Pain_Cage.jsonc)，必要任务覆盖在[幻痛囚笼.json](../../tasks/幻痛囚笼.json)。

3. 核查 `囚笼作战程序 → 耐力值不足 → 清除队伍` 及总次数不足路径，从难度页、准备页和提示弹窗均有明确有限处理；不可执行时记录原因后正常返回，不反复清队刷新预算。
4. 共享 [Role_Selection.jsonc](../../resource/base/pipeline/Role_Selection.jsonc) 仅在证据证明必要时修改；保留已接受的三处 ROI 修复并联查其他选人消费者。

## 3. FG-D08：首发空位与干净终局

### 已确认、推测与未验证

- 原证据：[台账 2.87](../iQOO16专项实施与验收-20261023.md)、[首跑 FAIL](../../build-debug/resume-20261026/s08-d08/d08-fail-receipt.json)、[复跑收据](../../build-debug/resume-20261026/s08-d08/d08-rerun-receipt.json)。
- 首跑五场后首发位为空，用户目击“首发位不能为空”；`点击作战开始` 无守卫导致约 40 分钟、260＋次无效点击，人工停止。
- [任务级覆盖](../../tasks/历战映射.json) 已增加 `点击作战开始.max_hit=20` 和 `作战开始.next` 尾部 `[JumpBack]返回`。复跑八场、每场一次作战开始、零无效连点，但仍 `effective_success=false`，由 ScopedRecovery 收尾。
- 首发位为何清空、复跑终止原因、正常领奖退出和次数／分数对账均未证实；周分上限仅为被后续续打削弱的假说。
- “13 场约 325 血清／疑似耗尽”属于已推翻的历史假说：2.88 实读血清 330／240 与 D08 跑前一致。不得再用该假说解释失败；原 FAIL 和原始收据不删除。

### 文件与实现工作

主消费者为 [HighRankMapping.jsonc](../../resource/base/pipeline/HighRankMapping.jsonc)、[Role_Selection.jsonc](../../resource/base/pipeline/Role_Selection.jsonc) 与[历战映射任务](../../tasks/历战映射.json)。

1. 在真实出战准备页区分“缺队长”“首发挂空位”“有队长但无首发”“正常首发”。不能以已选队长推定首发有效，也不能只在点 Start 后依赖短暂 toast。
2. 沿清队、队长和 `选择首发／选择首发_重新选人` 路径确认空位产生时点；只对明确阻塞做有限纠正。不能确认成员／首发时停止新增 Start 点击。
3. 保留现有 `max_hit=20`、返回兜底和用户配置的 `开始挑战.max_hit`。如需更精确的单场／无进展预算，另以可观察进展定义，不通过提高或删除上限解决阻塞。
4. 衔接 `开始挑战 → 继续挑战／结算 → 识别历战分数 → 领奖／返回`，对账配置刷取次数、实际场次及分数，分别识别有奖、已领、无可继续场次和真正失败。

## 6. 每个新用例的预算、证据与停止条件

开跑前在独立 ignored scope 中记录设备、当前 source revision／manifest、实际 loaded generation、Controller／VD、配置与任务实参、当前页和唯一输入执行者。新 scope／重连先按[项目设备策略](../开发与验证指南.md#项目级真机设备策略)复核，不把当前已改设置记成原值。

每个用例必须写明业务目标、最大墙钟时间、目标场次／房间数、纠正／重试／重开上限及跨重启累计额度；预算未明确时不启动。先跑能暴露单一状态的一场／单房用例，再按结果扩展；失败与恢复不能刷新累计预算。

- 外层任务与命令状态等待采用 **10 秒一探**。现有帧龄、输入停止检查和底层超时保持其合同，不改成 10 秒。
- 未知页、重复静止且无节点／业务进展、识别冲突、确认不了当前成员／首发或输入释放时，停止新增动作；达到本案上限后使用现有正常 UI Stop，并核同 run 原生终态。不得靠 force-stop、反复重装或取消上限掩盖失败。
- 原业务结果、Stop 请求／确认、恢复结果分别记录。ScopedRecovery、框架 COMPLETED、正常返回任一项均不能单独证明业务成功。
- 收尾分别核真实页面、无活动触点、任务与自有 helper／句柄终态；必要 UI 操作结束立即恢复现有 Manual 黑罩并核实际防锁／最低亮度。整体目标完成前继续承担原系统值与训练参数恢复责任，不随单案或 lease 结束还原。
- 日志、截图与私有配置先脱敏；不得将凭据、安装包或完整私有收据提交 Git。本计划的本机证据链接只作索引，缺失时明确标未取得，不重建原现场。
