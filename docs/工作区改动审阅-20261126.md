## 7. 全屏预览退出后一直横屏：根因与修复（20:50–21:10）

- 现象归属：用户报「熄屏挂机被去掉之后，界面横过来、而且不恢复」。排查结论是两条独立链路：**黑罩消失**由 `ScreenSaverOverlayManager` 的 `dismissByUser()`／`releaseRun()` 触发（已有真机时间线），**横屏**则是 App 自己的 `FullscreenPreview` 留下的方向状态。
- 代码事实（pinned `bc55dac4`）：整个 MaaFwApp 只有一处方向请求——`app/src/main/java/com/aliothmoon/maafw/ui/tasks/TasksPreviewSection.kt:252-259`，进入全屏预览设 `SCREEN_ORIENTATION_SENSOR_LANDSCAPE`，`onDispose` 只把 `requestedOrientation` 还原成进入前的值。`MainActivity` 的 `configChanges` 含 `orientation|screenSize`，主窗体进入前通常是 `SCREEN_ORIENTATION_UNSPECIFIED`。
- 为什么「还原」不生效：`UNSPECIFIED` 只是解除应用锁定方向，不等于把屏幕转回竖屏；自动旋转开着、手机平放时系统保持最后一次方向。真机系统层实测同构：`wm user-rotation lock 1` 后 display 0 变 `ROTATION_1`，`wm user-rotation free` 后 `accelerometer_rotation=1`、`user_rotation` 仍为 1、display 0 仍 `ROTATION_1`，只有显式 `wm user-rotation lock 0` 才回 `ROTATION_0`（实验后已恢复 `accelerometer_rotation=1 / user_rotation=0 / ROTATION_0`）。
- 修复：新增 overlay `app/src/main/java/com/aliothmoon/maafw/ui/tasks/PreviewOrientationRestore.kt`（纯决策函数：进入时仅在非横屏强制横屏；退出时先立即设 `PORTRAIT`，500 ms 后再把方向控制权交还进入前的值），`TasksPreviewSection.kt` 改为调用它；新增 JVM 单测 `PreviewOrientationRestoreTest.kt` 与 Python 补丁回归 `tests/test_preview_orientation_patch.py`，`install.yml` 的单测白名单同步加该类。
