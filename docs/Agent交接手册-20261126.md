## 2. 授权与完成口径

- 用户长期授权（原话）：「所有本项目关的游戏验证都可以真机验证，不用再反复问我」⇒ 设备侧验证不需逐次申请。**11-27 上午追加（原话）：「全部commit，但不要 push，后续推进时可以自主决定何时commit——但依旧不要主动push」** ⇒ 可以自主 commit（原 117 项已分 4 组提交到 `mine`，见 §3）；**push / 发布 / 换签名 / 装异签名包仍未授权**，也不代表可以自行消费非必要资源、改设备分辨率、动代理。
- **血清包（11-27 上午追加，原话）：「以后如果因为血清（我可能会叫成体力，总之是一个意思）不够，三四天内即将过期的临期血清直接用就行，不用问我。这个范围外的血清可以来问我是否使用，不要这样干等浪费时间」** ⇒ 验证被血清卡住时，血清页上过期标签为 `小时/1天/2天/3天/4天` 的包直接用；**不要为了等自然回复把实验排到几小时后**（回复是 6 分钟 +1）。**12:4x 再次纠正（原话：「我不是说了不要等，用血清啊」）**——我把「三四天内」卡成 ≤4 天、留着首卡 `5天` 的包去等回复，又被纠正 ⇒ `5天` 档同样直接用；「三四天内」是口语量级，拿不准某档算不算时默认按「用户想让我用」处理，并在汇报里写明用了哪个。现在只剩 `1周` 档，动它之前先问（问的同时别停工）。这条只授权 agent 为解锁验证而用包，pipeline 里 `吃体力药` 的策略仍是产品决策。
