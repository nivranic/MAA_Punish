## 2. 授权与完成口径

- 用户长期授权（原话）：「所有本项目关的游戏验证都可以真机验证，不用再反复问我」⇒ 设备侧验证不需逐次申请。**11-27 上午追加（原话）：「全部commit，但不要 push，后续推进时可以自主决定何时commit——但依旧不要主动push」** ⇒ 可以自主 commit（原 117 项已分 4 组提交到 `mine`，见 §3）；**push / 发布 / 换签名 / 装异签名包仍未授权**，也不代表可以自行消费非必要资源、改设备分辨率、动代理。

- **会话分工（11-27 上午，用户纠正侧聊的原话：「侧聊肯定是通过给主对话发消息来实现啊，哪有直接侧聊改的」）**：侧聊只答疑、只读取证、起草给主对话的消息；改时间表、杀/起后台编排进程、消耗游戏资源、改任务勾选、动设备状态，一律由主对话执行。起因：侧聊在 10:58 杀掉了主对话 13:26 档的编排器并用包重排，两边现场认知分叉。
- 完成口径：只要求**简体/繁体中文**适配；真机验收是证据来源，**不是产品完成门槛**；外语（日/英）缺口保留为历史记录，不阻塞。
- 结论纪律：`Tasker.Task.Succeeded` / 原生 `Succeeded` / App 判完成 / 账本 `done` **都不等于**真打赢、真领奖、真消费。凡未直接观察到结果，一律标「未验」。
