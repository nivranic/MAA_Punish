## 2. 本轮核心成果与铁律

1. **组跑杀组缺陷全链已修**（2.187 破案→2.189 修复）：`default_pipeline.json` 全节点 `on_error=["返回主菜单_err"]` → ScopedRecovery 拒肉鸽 → post_stop → App 判 task_not_terminal 杀组。修复=各模式接 StopTask 自然终局（DirectHit+StopTask+next=[]，仿矩阵循生身份拒绝停止模板）。
2. **R03 全链路实证**：战败→意识重启弹窗→`[JumpBack]放弃战斗`→链路崩溃结算→重进（run13 五连）；胜利→结算链→`肉鸽内部` 回环→再战（run14 两连胜）；run13 首次自然 `Tasker.Task.Succeeded` 且返回主菜单_err 零触碰。
3. **铁律（新）**：资源侧 next/on_error 引用的节点必须定义在**资源 bundle 内**；定义在 tasks/*.json pipeline_override 会导致资源加载整体失败（加载期校验，对照实验确认）。任务级 override 只能自闭合引用。
4. **运维铁律（沿用+强化）**：shell 覆写 pi 后必须重启 App（FUSE 陈旧缓存）；App 重启后 VD 重建（`cmd display get-displays` 查逻辑 id，`dumpsys SurfaceFlinger --display-id` 查 screencap token，两者不同且每 boot 变）；**VD 只在点开始任务时创建**——先点开始任务→查 VD→`am start --display <VD>` 拉游戏（冷启动约 45s，在 entry 预算内）；开始任务按钮 (522,2809)，任务 tab (540,2996)，模式行勾选框 x≈155（uiautomator 的 checked 属性恒 false，只能截图看）。
5. **R05 神寂启示录首探结论**：链多处 `next=null` 地雷已修（对局结束/战斗失败/推演/继续）；答案多问循环已接；主调度器（`神寂启示录` 节点 reco 恒真 22 候选）是该模式的自愈枢纽。真实战斗/战败/對局結束结算/日耗尽态均未观测到。
